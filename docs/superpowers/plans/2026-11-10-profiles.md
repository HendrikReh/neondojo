# Profiles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Preserve all unrelated working changes. Do not start implementation merely because this plan exists.

**Goal:** Vollständige benannte Konfigurationsprofile mit explizitem Speichern, zentral gesicherter aktueller Konfiguration, Verwaltung in Einstellungen und sicherem Wechsel über die Kopfzeile einführen.

**Architecture:** PostgreSQL verwaltet Profilstände und eine installationsweite aktuelle Konfiguration. Ein React-Provider führt alle Einstellungsänderungen durch einen serialisierten Schreibkanal; vorhandene App-/Book-Settings sind transaktional gepflegte Projektionen für bestehende Verbraucher. Laufende Analysen und Spielsitzungen behalten ihre Snapshots.

**Tech Stack:** Vorhandenes Rust/Axum/SQLx/PostgreSQL, React 19/TypeScript/Vite, Vitest, Playwright, OpenAPI/utoipa. Keine neue Zustandsbibliothek erforderlich.

```ts
it("does not let an old autosave replace a profile activation", async () => {
  // Testadapter hält den ersten PUT zurück und protokolliert Mutationen.
  const { store, server } = createStoreHarness();
  server.holdNextWrite();
  store.updateCurrent((c) => ({
    ...c,
    appearance: { ...c.appearance, mode: "dark" },
  }));
  const flushed = store.flush();
  const switched = store.activateProfile(server.secondProfile.id, "keep");
  expect(server.writeMethods()).toEqual(["PUT /configuration"]);
  server.releaseHeldWrite();
  await flushed;
  await switched;
  expect(server.writeMethods()).toEqual([
    "PUT /configuration",
    `POST /profiles/${server.secondProfile.id}/activate`,
  ]);
  expect(store.getSnapshot().confirmed.active_profile.id).toBe(
    server.secondProfile.id,
  );
});
```

Zusätzlich prüfen: ältere Antworten nach Reload, zweimaliges Klicken, Storagefehler, Timeout nach erfolgreichem Commit, Journal-/Basisrevisionkonflikt.
