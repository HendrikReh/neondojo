# Four-ply analysis implementation plan

**Goal:** Offer GNUbg 4-ply for positions, dice distributions, individual games and entire matches, retaining 2-ply as the default.

**Design:** Extend the existing analysis profile from 0–3 to 0–4. All job types already pass their selected depth to GNUbg. Widen validation and database constraints, advertise the capability in OpenAPI and engine metadata, and extend the existing controls. Preserve settings revisions, previous jobs and analysis provenance. The separate future play profile remains 0–2.

**Architecture:** Rust/Axum/SQLx use a new additive migration; React shares the supported analysis depths. Native tests capture actual GNUbg output so a requested depth echoed in metadata cannot masquerade as a real 4-ply search. Existing pruning and bounded process execution remain in place.
