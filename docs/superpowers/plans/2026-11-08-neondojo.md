# Neondojo Implementation Plan

**Goal:** Import einer echten Partie, schnelle Suche und persistente lokale GNUbg-Analyse über eine browserfähige API.

**Architecture:** Rust-Modulgrenzen für Import, Engine, Datenbank, Job-Worker und HTTP. React spricht REST/SSE; PostgreSQL enthält die dauerhafte Wahrheit.

**Tech Stack:** Rust, Tokio, Axum, SQLx, PostgreSQL 17, GNUbg, React, TypeScript, Vite.

- [x] `backend/src/import/`: Zuerst Parserfälle für MAT/SGF/XG und beschädigte Eingaben testen. Normalisierung und Positionsrekonstruktion implementieren. Echte XG-Referenz verifizieren.
- [x] `backend/migrations/`, `backend/src/store.rs`: Transaktionalen Import mit Duplikaterkennung, Suchindizes und Cursor-Abfragen implementieren. Mit PostgreSQL Integrationstest prüfen.
- [x] `backend/src/engine.rs`, `backend/src/jobs.rs`: GNUbg-Aufruf mit festen Kommandos und temporären Dateien; Positionsanalyse und 21-Paar-Distribution. Dauerhafte Jobzustände und Ereignisse mit Lease/Retry. Echte Engine im Test ausführen.
- [x] `backend/src/api.rs`, `backend/src/main.rs`: REST, SSE-Replay, Uploadlimits und generierte OpenAPI. HTTP-Test für Import → Suche → Auftrag → SSE → Ergebnis.
- [x] `web/`: React/TypeScript-Client mit Import, Suchliste, Brett, Navigation, Analyse, Würfelmatrix und drei Themes. Typecheck/Build und Browserfluss prüfen.
- [x] `README.md`, `compose.yaml`, `scripts/`: Reproduzierbarer lokaler Start und dokumentierte Grenzen. Formatierung, Clippy, Tests, Build, Suchplan und Review ausführen.

## Gemeinsamer Importvertrag

`import::parse_sgf(&str) -> anyhow::Result<ImportedMatch>` und `import::xg_to_sgf(&[u8]) -> anyhow::Result<String>`.
`ImportedMatch { players: [String; 2], match_length: i32, positions: Vec<ImportedPosition> }`.
`ImportedPosition { game_no: i32, ply: i32, player: i32, dice: [i32; 2], board: Vec<i32>, position_id: String, match_id: String, notation: String }`.
Board: 26 Felder, Weiß positiv bewegt 24→1 mit Bar 25, Schwarz negativ bewegt 1→24 mit Bar 0. Spieler 0=Weiß, 1=Schwarz. Position vor dem Zug. GNUbg Position-ID und Match-ID enthalten das zum Analysezeitpunkt nötige Brett bzw. Spielkontext.

HTTP: `GET /api/health`, `POST /api/imports` (multipart `file`), `GET /api/matches?q=&after=&limit=`, `GET /api/matches/{id}`, `GET /api/positions?match_id=&position_id=&after=&limit=`, `GET /api/matches/{id}/dice`, `POST /api/jobs` (`position_id`=UUID, `kind`=`analysis|dice`, `plies`=0..2), `GET /api/jobs/{id}`, `GET /api/jobs/{id}/events`, `GET /api/openapi.json`.
