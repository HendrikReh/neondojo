# Playing feedback modes implementation plan

User approved four modes on 2026-11-09: competition, training, coach (default), tutor. Tutor threshold defaults to 0.04 and is independent of existing severity thresholds 0.04/0.08/0.16.

Architecture: capture mode, tutor threshold, automatic training feedback and analysis depth per session. A durable pending decision separates analysis/feedback from native commit so neither dice nor bot advance while reviewing. First attempts, retries and revealed assistance survive reload. Existing engine version/path and optimistic session revisions remain authoritative. Preserve current uncommitted project work and use its feature branch because the playing implementation is not committed yet.

- [x] Backend domain and settings: add validated persisted defaults and backward-compatible serde fields. New sessions default coach; legacy sessions preserve competition behavior. Extend OpenAPI from Rust.
- [x] Backend feedback: assess checker choices (including choices outside top candidates) and cube roll/double/take/drop in exact saved match context at captured analysis depth; versioned pending feedback, reveal/retry/hint and explicit continuation. Persist original choice before reveal and keep it for performance evaluation. Competition suppresses live feedback; completed matches expose review. Failure must not play dice, move checkers or overwrite checkpoint. Native forced actions must not trigger false errors.
- [x] Browser client: shared policy/types and translated mode selector, explanations, separate tutor threshold in Playing settings. Coach default; training automatic-analysis preference. Add feedback component with neutral tutor prompt and three actions; show only delta values for Coach. Training includes equities and probabilities. Hints are available on demand outside Competition. Disable normal board actions while feedback awaits continuation. Reload restores the saved panel and original attempt.
- [x] Statistics/review: keep assistance and mode with decisions; display original attempts and played choices separately; show no live assessment in Competition. Use the existing native PR definition where available rather than invent a PR denominator. Distinguish assisted learning results from independent competition.
- [x] Tests first: settings validation/defaults; persisted decision transitions, thresholds, original-choice retention, stale versions, cube perspective and native scoring; browser mode panels, Coach redaction, Tutor reveal/retry/reload, Competition hidden analysis and keyboard/board locking.
- [x] Verification: focused Rust and Vitest tests, native PostgreSQL/GNUbg integration, TypeScript production build, targeted browser tests, Rust format/clippy, then review changed paths and document final behavior. Do not stage or commit unrelated existing work.
